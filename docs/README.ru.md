# StructView

Быстрый кроссплатформенный просмотрщик и редактор структурированных данных.
Приложение показывает JSON, YAML, TOML и JSON5 в виде интерактивного дерева,
строит блок-схемы из JSON/YAML/TOML и Mermaid, импортирует графы Graphviz DOT,
GraphML и GEXF для просмотра и преобразования,
а также предоставляет headless-команды для форматирования, проверки, поиска,
сравнения, редактирования и экспорта таблицы, схемы и графа.

Английская версия документации находится в [основном README](../README.md).

Пошаговые руководства: [English](tutorial/en.md) | [Русский](tutorial/ru.md) |
[API-сервер графа](tutorial/api-server.ru.md).

## Возможности

- поддержка JSON, YAML, TOML и JSON5;
- построение блок-схем из JSON/YAML/TOML с распознаванием фигур узлов и импорт
  Mermaid;
- импорт графов Graphviz DOT, GraphML и GEXF только для чтения с
  преобразованием в JSON, YAML, TOML или JSON5;
- автоматическое определение формата для stdin и файлов с неизвестным
  расширением;
- интерактивное дерево объектов и массивов с раскрытием и сворачиванием
  узлов;
- полнотекстовый поиск по ключам, значениям и JSON-путям;
- фильтры поиска по области (ключи/значения/пути), регистру, точному и
  целому совпадению, а также регулярные выражения;
- конструктор регулярных выражений с экранированным обычным текстом и готовыми
  фрагментами шаблонов;
- переключение между деревом, графом связей, плоской таблицей и диаграммой
  схемы;
- распознавание CSS-цветов и образцы цветов в представлениях значений:
  именованные цвета, HEX, RGB/HSL/HWB, Lab/LCH, OKLab/OKLCH и функции CSS
  `color()`;
- отдельная схема структуры JSON/YAML/TOML с узлами в исходном порядке,
  сворачиванием, тремя раскладками, поиском, масштабированием и экспортом SVG/PNG;
- построение связей по распространённым идентификаторам и полям-ссылкам;
- необязательный авторизованный API анимации графа: сценарии камеры и эффектов,
  постоянные realtime-маркеры и независимо управляемые задания;
- именованные задания с этапами, прогрессом, статусами, подсказками при наведении
  и списком с переходом к месту выполнения; несколько заданий на общих узлах
  и маршрутах;
- экспорт строк таблицы в CSV с учётом активного фильтра поиска;
- просмотр JSON Schema и схем OpenAPI (компонентных и встроенных в пути API);
  для обычных документов показывается выведенная из примера структура;
- редактирование и сохранение дат/времени TOML с сохранением их родного типа;
- режим редактирования полей и примитивных значений;
- выбор цвета для строковых значений и атрибутов графа с возможностью выбрать
  цвет со снимка экрана, сразу применить формат записи или сохранить исходную
  нотацию; маркер палитры увеличивается только при наведении или перетаскивании;
- создание нового пустого файла JSON, YAML, TOML или JSON5 прямо в режиме
  редактирования;
- добавление полей объектов и элементов массивов;
- конструктор полей с выбором типа: строка, число, логическое значение, null,
  объект, массив и дата/время TOML;
- сохранение редактируемых документов в выходные форматы и преобразование
  импортированных графов в эти форматы;
- копирование значения, ключа и пути узла через контекстное меню;
- выбор и копирование нескольких структур с сохранением иерархии;
- вставка скопированных структур в другой открытый файл;
- сравнение двух и более структурированных файлов с отображением изменённых
  путей;
- парный diff для любых двух выбранных файлов с подсветкой добавлений,
  удалений и изменений;
- светлая и тёмная тема;
- локализация GUI на русский и английский языки;
- работа из командной строки без запуска GUI.

## Поддерживаемые форматы

| Формат | Расширения | Доступ |
| --- | --- | --- |
| JSON | `.json` | Чтение и запись |
| YAML | `.yaml`, `.yml` | Чтение и запись |
| TOML | `.toml` | Чтение и запись |
| JSON5 | `.json5` | Чтение и запись |
| Mermaid flowchart | `.mmd`, `.mermaid` | Импорт, только чтение |
| Graphviz DOT | `.dot`, `.gv` | Импорт, только чтение |
| GraphML | `.graphml` | Импорт, только чтение |
| GEXF | `.gexf` | Импорт, только чтение |

Для файлов формат сначала определяется по расширению. Если расширение
неизвестно, содержимое разбирается методом автоматического определения. Для
stdin формат определяется по содержимому.
Файлы GraphML и GEXF с расширением `.xml` определяются по корневому XML-элементу.

Mermaid, DOT, GraphML и GEXF преобразуются в граф с полями `graph`, `nodes` и
`edges`. JSON, YAML и TOML также могут задавать граф напрямую: `graph.type =
"flowchart"`, узлы с полями `id`, `label` и необязательным `shape`, а рёбра —
с `source`, `target` и `label`. Поддерживаются фигуры `process`, `terminator`,
`decision`, `input_output`, `preparation`, `subprocess`, `database` и
`connector`. Mermaid преобразует распространённые формы узлов и подписи рёбер
в эти поля.
Используйте `Файл -> Преобразовать в` в GUI или, например,
`struct_view format network.graphml --output network.json`, чтобы сохранить
нормализованные данные в JSON, YAML, TOML или JSON5. Исходный файл графа
доступен только для чтения и не перезаписывается. Схемы и примеры приведены в
[руководстве по графам](./tutorial/ru.md).

Нестрочные ключи YAML сохраняются при записи в YAML. Преобразование такого
документа в JSON или TOML завершается ошибкой вместо незаметного изменения
типа ключей.

## Установка и сборка

Для сборки требуется Rust с поддержкой `edition 2024` и Cargo.

На Debian/Ubuntu сначала установите системные зависимости для сборки:

```sh
sudo apt-get update
sudo apt-get install --yes \
  build-essential pkg-config libclang-dev libdbus-1-dev libegl-dev libgbm-dev \
  libpipewire-0.3-dev libwayland-dev libx11-dev libx11-xcb-dev \
  libxcb1-dev libxcb-randr0-dev libxcb-render0-dev libxcb-shape0-dev \
  libxcb-xfixes0-dev libxcb-xinput-dev libxcb-xinerama0-dev \
  libxkbcommon-dev libxkbcommon-x11-dev libxrandr-dev
```

Пакет `libegl-dev` предоставляет файл `egl.pc`, который `khronos-egl` ищет
через `pkg-config`. Пакет `libgbm-dev` предоставляет `libgbm.so` для линковки
с `-lgbm`. Эти системные зависимости нужны при сборке, даже если планируется
использовать только командный режим.

```sh
git clone https://github.com/PavelKotDRM/structview.git
cd structview
cargo build --release
```

После сборки исполняемый файл находится в `target/release`:

- Windows: `target\release\struct_view.exe`;
- Linux и macOS: `target/release/struct_view`.

На Linux для запуска графического режима необходим доступный графический
сервер X11 или Wayland. Если графический сервер недоступен, используйте
командный режим.

Предварительно собранные архивы версий доступны в
[GitHub Releases](https://github.com/PavelKotDRM/structview/releases).

## Графический интерфейс

### Сочетания клавиш

Откройте **Помощь -> Сочетания клавиш** или нажмите **F1** в любом
представлении, в том числе при вводе текста. В прокручиваемом окне перечислены
все командные сочетания, навигация и жесты диаграмм. Esc закрывает справку;
повторное нажатие F1 оставляет её открытой.

Если сервер API запущен, в справке также отображается понятный обзор OpenAPI:
адрес сервера, требования к авторизации и описание доступных операций.
Полная спецификация JSON открывается в отдельном изменяемом по размеру окне.

| Сочетание | Действие |
| --- | --- |
| F1 | Открыть справку по сочетаниям клавиш |
| Ctrl+N / Ctrl+O | Создать / открыть файл |
| Ctrl+S / Ctrl+Shift+S | Сохранить / сохранить как (включая исходник структуры) |
| Ctrl+W | Закрыть файл с подтверждением несохранённых изменений |
| Ctrl+F | Открыть поиск и перевести фокус в строку запроса |
| F3 / Shift+F3 | Следующее / предыдущее совпадение |
| Esc | Закрыть поиск без очистки запроса |

В macOS вместо Ctrl используется Cmd. В текстовых полях сохраняются
собственные сочетания копирования, вставки, отмены и повтора.

### Схема структуры данных

`Вид -> Представление -> Схема структуры данных` доступна и без открытого документа. Это
независимый режим: он рисует иерархию файла как узлы и родительские рёбра,
не выводит произвольные связи и не использует модель графа связей.
При первом входе текущий файл читается как отдельный снимок с диска;
несохранённые правки других режимов сюда не переносятся. Комментарии JSON5,
YAML и TOML отображаются отдельными узлами и добавляются через конструктор
в режиме редактирования.

Выберите **Файл -> Открыть**, перетащите один файл либо откройте
**Вид -> Исходный текст** и вставьте JSON/JSON5/YAML/TOML в окно исходника.
Формат выбирается в **Настройки -> Формат данных -> Авто / JSON / JSON5 / YAML / TOML**,
построение запускается через **Файл -> Построить схему**. Разбор выполняется в фоне. Ошибки
показывают номер строки; последняя корректная схема сохраняется с явным
предупреждением, что текст изменился.
При ошибке открывается полный исходный текст для исправления; предпросмотр
выбранных узлов недоступен до успешного повторного построения схемы.
Открытие другого файла закрывает прежний диалог редактирования поля.
Исходный текст сохраняется без преобразования, даже если он пустой; во время
загрузки или построения схемы команды сохранения недоступны.

В **Вид -> Раскладка структуры** доступны раскладки сверху вниз, слева направо
и компактная. В компактной раскладке (по умолчанию) соседние свёрнутые
контейнеры и конечные узлы собираются в сбалансированные сетки вместо
одной длинной линии. Порядок исходника сохраняется: слева направо, затем
сверху вниз. Раскрытая ветвь получает отдельное место для продолжения дерева
без наложения на соседние группы; сворачивание возвращает компактную группировку.
Раскладки сверху вниз и слева направо сохраняют прежнее расположение вдоль одной оси.
Масштаб, 100%, вписывание, выбор всех узлов, очистка выбора, раскрытие выбранного узла
и **Показать следующие 100 элементов** также находятся в **Вид**. Клик по контейнеру
выделяет его; кнопка раскрытия сворачивает/разворачивает и выделяет контейнер.
Крупные контейнеры и глубокие ветви изначально
свёрнуты; при раскрытии показываются первые 100 потомков. Выберите родителя
и нажмите **Показать следующие 100 элементов**, чтобы раскрыть следующую
порцию. Счётчик структуры учитывает и скрытые узлы.

Порядок ключей внутри родителя сохраняется. Составные таблицы TOML группируются
по иерархии. Анкоры YAML подписаны, алиасы (включая рекурсивные) остаются
листьями-ссылками без дополнительных рёбер. Поток YAML из нескольких
документов получает общий корень-массив.

Оба режима диаграмм используют одинаковые команды масштаба, выбора и экспорта
в главном меню. Прежние **Развернуть всё / Свернуть всё** доступны в
**Вид -> Действия с деревом**; раскрытие структуры сохраняет порционную выдачу
для больших контейнеров.

Поиск возвращён в общее окно расширенного поиска: кнопка лупы,
**Правка -> Расширенный поиск** или Ctrl/Cmd+F. Для обоих режимов доступны
одинаковые фильтры ключей/значений/путей, регистр, точное и целое совпадение,
регулярные выражения, конструктор и список результатов.
Ctrl/Cmd+F переводит фокус в строку запроса, даже если фокус уже находится
в другом поле или на холсте. F3 / Shift+F3 выбирают следующее / предыдущее
совпадение; Esc закрывает поиск, сохраняя запрос.
Переход к результату раскрывает нужных родителей и скрытые порции, центрируя узел.
Выбранный узел подсвечивает путь до корня. Наведение показывает полный ключ,
значение и путь JSON Pointer.

Перетаскивайте холст для панорамирования, используйте колесо или +/- для
масштаба. В фокусе холста или узла: вверх/вниз — выбор, влево —
свернуть/родитель, вправо — развернуть/потомок, Enter/Space — переключить
раскрытие, Home — вписать схему. Ctrl/Cmd+F открывает общее окно поиска.
На самом холсте показана только диаграмма; путь и значение выбранного узла,
имя файла, формат, число узлов и масштаб находятся в статусной строке.
Полный текст выбранного узла доступен по наведению. Панели управления
над схемой нет. Легенда цветов, подсказка навигации и пояснение об исходнике
находятся в **Помощь -> Легенда и управление диаграммами**.
В легенде показаны цветные образцы и типы узлов с названием цвета в скобках,
без повторного текстового описания. Управление оформлено наглядными клавишами
и обозначениями жестов рядом с действиями: общие команды и особенности режимов
сгруппированы отдельно.
При сворачивании и разворачивании ветви её узел автоматически выделяется и центрируется
без изменения масштаба. Во всех режимах поля статусной строки разделены
разделителями GUI вместо `|`, название режима в статусе не повторяется.
Версия приложения и все сведения о сборке вынесены в отдельный подпункт
**Помощь -> Информация о сборке**.
В обоих режимах обычное перетаскивание двигает холст, колесо/жест меняет
масштаб относительно указателя, +/- меняют масштаб, Home вписывает диаграмму.
В фокусе холста или узла вверх/вниз выбирают предыдущий/следующий узел.
В графе связей влево/вправо переходят к входящему/исходящему соседу
(или другому связанному узлу, если соседа в этом направлении нет),
Enter/Space выбирают текущий узел. Ctrl/Cmd+клик переключает множественный
выбор; Shift+перетаскивание выделяет рамкой, а Ctrl/Cmd+Shift+перетаскивание
добавляет к выбору. Сворачивание ветвей остаётся действием структуры данных.
При наведении на линию связи открываются её данные, а на пересечении —
список близких связей. Удерживайте Ctrl/Cmd, пока переводите указатель с линии
во всплывающее окно; отпустите клавишу над окном, чтобы прокрутить его.
Маршрутизатор разводит длинные общие участки по соседним дорожкам, если есть
свободное место; на плотной раскладке линии могут пересекаться.
Нативные метки AccessKit содержат полный текст узлов; за пределами экрана
узлы не отрисовываются. Глубина входной структуры ограничена 128 уровнями,
чтобы вместо переполнения стека показывать ошибку.

**Файл -> Экспорт диаграммы -> SVG / PNG** сохраняет всю текущую раскрытую
раскладку, включая узлы вне экрана, без временной подсветки. Скрытые ветви
и ещё не раскрытые порции не экспортируются. SVG содержит полные значения
в подсказках; PNG при необходимости пропорционально уменьшается до
16 миллионов пикселей. Экспорт выполняется в фоне. В обоих режимах доступны
одинаковые варианты оформления: светлый с прозрачным фоном и тёмный с
непрозрачным фоном, независимо от темы приложения.

Запуск без аргументов открывает пустое окно приложения:

```sh
struct_view
```

Файл можно открыть сразу при запуске:

```sh
struct_view data.json
```

Открыть сразу несколько файлов в режиме сравнения:

```sh
struct_view first.json second.yaml third.toml
```

Также файл можно выбрать через меню `Файл -> Открыть…` или перетащить его в
окно. Отдельный файл читается и разбирается в фоне; индикатор загрузки
отображается в строке состояния. Для сравнения используйте
`Файл -> Сравнить файлы…` и выберите два или более файла.
Для создания нового файла выберите `Файл -> Создать файл…`, укажите имя с
расширением `.json`, `.yaml`, `.yml`, `.toml` или `.json5`, после чего
добавляйте поля в пустой объект кнопкой `+` рядом с ним в режиме редактирования.
Для TOML тип `null` недоступен, поскольку этот формат не поддерживает
нулевые значения.

В схеме структуры данных выбранные узлы (включая целые объекты и массивы)
копируются через `Правка -> Копировать`, `Ctrl+C` или контекстное меню узла.
В режиме редактирования их можно вставить в выбранный объект или массив через
`Правка -> Вставить`, `Ctrl+V` или пункт `Вставить сюда` в контекстном меню
контейнера — так же, как в дереве JSON.

В интерфейсе доступны:

- адаптивное меню с разделами `Файл`, `Правка`, `Вид`, `Настройки` и `Помощь`;
  на узком экране они собраны в один пункт `Меню`;
- меню `Файл` для создания, открытия, сохранения, преобразования в другой
  формат, сохранения в новый файл и закрытия документа;
- переключатель представлений: интерактивное дерево, граф и блок-схема, плоская
  таблица и диаграмма схемы;
- граф по идентификаторам и ссылкам, а также явные графы и блок-схемы
  ориентированные, неориентированные, взвешенные и мультиграфы; списки
  смежности и матрицы; TOML-графы сущностей и связей, двудольные и
  многодольные графы; импорт DOT, GraphML и GEXF только для чтения.
  Мультиграфы сохраняют параллельные связи. Форматы описания и преобразования
  с примерами приведены в [руководстве по графам](./tutorial/ru.md). Раскладка
  вычисляется в фоне; во время расчёта отображается индикатор.
  Пересечения линий допустимы, но совпадающие участки и проход через узлы
  запрещены. Маршруты ортогональны: выровненные порты соединяются прямой линией.
  Остальные связи идут с изломами, кроме случая, когда порты можно соединить одним
  прямым отрезком: тогда связь рисуется этим отрезком, если он не длиннее двух
  колонок раскладки (680 точек), не задевает карточки, не подходит ближе восьми
  точек к концам и изломам других связей и пересекает не более одной другой связи.
  Такие прямые связи выбираются после того, как ортогональная раскладка окончательна,
  поэтому не меняют маршруты других связей. Связи между колонками раскладки
  выходят и входят через обращённые друг к другу левую и правую стороны, поэтому
  связи идут слева направо; у узла с более чем семью связями каждая его связь
  выходит через сторону, геометрически обращённую к другому концу связи, потому
  что левая или правая сторона вмещает лишь около семи дорожек. Карточки с более
  чем 22 связями становятся шире примерно на 8 точек на связь, чтобы каждой связи
  хватило собственной дорожки на верхней или нижней стороне; такие большие
  карточки также показывают число входящих и исходящих связей и путь узла в
  документе. Маршрут минимизирует длину плюс
  фиксированную стоимость каждого излома (включая повороты у портов), не делает
  петель вокруг собственных подводов, среди равноценных вариантов оставляет
  свободными прямые выходы других портов и центрируется относительно средней
  линии между своими выходами, поэтому параллельные связи собираются в
  симметричный пучок.
  Подводы к портам резервируются, чтобы чужие маршруты их не занимали.
  Промежутки увеличиваются только рядом с узлами, у которых много связей.
  Если места всё ещё недостаточно, повторные расчёты расширяют только
  промежутки вокруг рёбер, которым не хватило места, и пересчитывают порты
  и маршруты; наложения участков остаются запрещены. Ещё до двух проходов
  расширяют промежутки вокруг маршрутов, которым другие рёбра навязали
  лишние изломы или обходы.
  Числовые маркеры вынесенных подписей не перекрывают наконечники стрелок,
  включая резервное размещение на плотных графах и экспорт SVG/PNG;
- таблица пути, значения и типа; она использует фильтр поиска и экспортирует
  строки в CSV;
- диаграмма JSON Schema и компонентных/встроенных схем OpenAPI; для остальных
  данных схема выводится из примера и явно помечается как не являющаяся
  контрактом;
- таблица сравнения всех выбранных файлов и парный diff двух выбранных версий
  с подсветкой добавленных, удалённых и изменённых значений;
- кнопки разворачивания и сворачивания всего дерева;
- окно поиска и диалоги добавления/редактирования сначала открываются внутри
  главного окна; через кнопку меню с тремя точками выберите `Отделить окно`, а для возврата
  нажмите `Прикрепить окно` в верхней части отдельного окна;
  поиск открывается кнопкой на панели или `Ctrl+F` (`Cmd+F` в macOS) и содержит
  список путей с переходом к предыдущему и следующему совпадению;
- настройки поиска по ключам, значениям и путям, учёта регистра, точного и
  целого совпадения, а также регулярных выражений Rust;
- конструктор регулярных выражений для добавления экранированного текста и
  готовых фрагментов шаблонов;
- режимы `Просмотр` и `Редактирование`;
- отмена и повтор последних 100 изменений документа; inline-правки объединяются
  в одно действие (`Ctrl+Z` / `Ctrl+Y`, на macOS — `Cmd+Z` / `Cmd+Shift+Z`);
- добавление полей и элементов видимой кнопкой `+` рядом с каждым объектом и
  массивом; имя и тип вводятся вручную через конструктор, а вложенные
  структуры заполняются тем же способом;
- добавление комментариев документа для JSON5, YAML и TOML, а также YAML-тегов
  через конструктор;
- редактирование любого узла через `Редактировать поле…` в контекстном меню,
  включая смену типа и переименование полей объектов;
- выбор узлов кликом; `Ctrl`/`Cmd` + клик добавляет узел к текущему выбору;
- копирование выбранных структур через `Правка -> Копировать`, `Ctrl+C` или
  контекстное меню;
- вставка в выбранный объект или массив через `Правка -> Вставить`, `Ctrl+V`
  или пункт `Вставить сюда` в контекстном меню контейнера;
- горизонтальная прокрутка верхней панели колесом мыши, если элементы
  управления не помещаются по ширине окна; полоса прокрутки не закрывает
  элементы панели;
- переключение языка через `Настройки -> Язык`;
- контекстное меню узла для копирования значения, ключа или пути;
- добавление полей и элементов в режиме редактирования;
- переключение светлой и тёмной темы.

### Редактор графа связей

В представлении «Граф и блок-схема» команда **Файл -> Создать граф**
открывает пустой несохранённый граф в режиме редактирования. Команда
**Правка -> Режим -> Редактирование** автоматически создаёт редактируемую копию,
если текущий граф ещё нельзя редактировать. Это работает для автоматически найденных
связей, блок-схем и импортированных DOT/GraphML/GEXF/Mermaid; исходный файл не
изменяется. Копия блок-схемы сохраняет тип и фигуры узлов, которые можно менять
в редакторе. Перед заменой документа приложение предлагает сохранить
несохранённые изменения.

Окно **Вид -> Редактор графа** содержит списки сущностей, связей и групп.
Оно открывается внутри главного окна, изменяет размер и перемещается независимо
от холста. Двойное нажатие на заголовок сворачивает или разворачивает встроенное
окно. Через меню с тремя точками выберите **Отделить окно**, а в отдельном
окне — **Прикрепить окно** для возврата, как в окне поиска.
Закрытое окно можно снова открыть через «Вид».
Команды **Добавить сущность**, **Добавить связь**, **Добавить группу**
и **Свойства графа** находятся в меню **Правка** и дублируются кнопками
в верхней части окна редактора, в том числе после его открепления.
Команды графа скрыты в других представлениях; окно редактора и команды изменения
доступны только для редактируемого графа в режиме редактирования.
Возможности редактора:

- создание, переименование, дублирование и удаление сущностей и связей;
- выбор фигуры узла блок-схемы: процесс, начало/завершение, решение, ввод/вывод,
  подготовка, подпроцесс, база данных или соединитель;
- выбор исходной и целевой сущности, включая петли и параллельные связи;
- направленные, ненаправленные, двунаправленные и обратные связи,
  необязательный числовой вес, единица веса, подписи и типизированные атрибуты
  в виде JSON-объекта;
- создание и переименование групп, назначение сущностей группам и удаление
  группы без удаления её сущностей;
- кнопка **Применить и создать связанную сущность** в диалоге сущности:
  новая сущность создаётся сразу со связью от текущей;
- открытие редактора из списка или двойным нажатием на узел либо подпись
  связи; связи без подписи доступны через список связей.

Удаление сущности после подтверждения также удаляет все её связи.
Изменения поддерживают общую историю отмены и повтора.
Размещение узлов и прокладка связей всегда автоматические: перетаскивание
двигает холст, а не отдельный узел. Группы участвуют в автоматической раскладке;
при наличии групп сущности без группы получают отдельную колонку.
Направление в свойствах графа применяется только к новым связям.

Команды **Сохранить / Сохранить как** сохраняют редактируемый граф в JSON,
JSON5, YAML или TOML. Экспорт SVG/PNG использует автоматическую раскладку.
На холсте и при экспорте в SVG и PNG вынесенная легенда связей выровнена по строкам и колонкам:
номерные кружки занимают отдельное место перед подписями независимо от их длины.
Формат редактора содержит `graph.editor_version: 1`,
`graph.type: "mixed_multigraph"`, массивы `nodes`, `edges` и `partitions`
с именами групп; поле сущности `partition` задаёт имя группы.
ID должны быть непустыми и уникальными, концы связей — существующими.
В копии сохраняется нормализованный типизированный снимок исходных данных
в `graph.source_document`, включая специфичные для исходного формата сведения.
Исходные записи сущностей сохраняются в атрибутах; распознанные числовые веса
становятся редактируемыми весами, остальные атрибуты подсказок связей
сохраняются как текст. Правки копии не переносятся обратно в оригинал.

Поле **Атрибуты** содержит только дополнительные данные. **Уникальный ID**
и **Имя / подпись** — основные поля `id` и `label`, а не содержимое
`attributes`; они сохраняются и при пустом объекте атрибутов.
Разверните **Полный JSON элемента (предпросмотр)** в диалоге сущности,
связи или свойств графа, чтобы видеть все текущие поля вместе.
Предпросмотр доступен только для чтения и обновляется при вводе.
Некорректный JSON атрибутов или вес отображает ошибку вместо устаревшего JSON.

### API анимации графа

Откройте «Граф и блок-схема» и дождитесь окончания расчёта раскладки.
Выберите **Настройки -> API анимации графа**, чтобы открыть отдельное окно
настроек. Его можно открепить и вернуть в главное окно. Включите сервер API.
Порт `0` означает выбор свободного порта; можно задать конкретный порт до
включения. Окно показывает фактический адрес `http://127.0.0.1:ПОРТ` и
Bearer-токен, который можно выделить и скопировать. Каждый запрос требует
заголовок `Authorization: Bearer ТОКЕН`.

API по умолчанию выключен; начальный адрес — IPv4 loopback. Проверяет настроенный
`Host` и отклоняет запросы с браузерным `Origin`. Используйте локальный или сетевой скрипт
или другое нативное приложение, а не страницу браузера. Не передавайте токен
посторонним. **Выключить API** закрывает порт и останавливает анимацию.
При следующем включении создаётся новый токен; токен и включённое состояние
не сохраняются между запусками.

Для демонстрации API на блок-схеме откройте
[`tests/fixtures/FlowchartAnimationDemo.toml`](../tests/fixtures/FlowchartAnimationDemo.toml),
выберите представление **Граф и блок-схема**, дождитесь расчёта и включите
сервер в окне API. Python-контроллер и пошаговый сценарий запуска описаны в
[инструкции к демо](../tests/README.md). В качестве альтернативы доступен
пример интернет-магазина [`GraphAnimationDemo.toml`](../tests/fixtures/GraphAnimationDemo.toml);
передайте его контроллеру через `--graph`.

В окне API доступны **Копировать токен**, **Вставить токен**, **Применить токен**
и **Сгенерировать новый токен**. Собственный токен должен содержать 16–256
печатных ASCII-символов без пробелов; используйте длинный случайный секрет.
Смена применяется сразу без перезапуска сервера и остановки анимации.
Старый токен больше не принимается для новых запросов; уже авторизованные
запросы могут завершиться. Перезапустите внешние контроллеры с новым токеном.
Токены не сохраняются.

Сервер управляет тремя независимыми визуальными слоями:

| Слой | Назначение | Время жизни и очистка |
| --- | --- | --- |
| Сценарный (`/v1/animation`) | Один сценарий камеры, подсветки и движения по времени | Новый сценарий заменяет старый; сценарный `clear` очищает только этот слой |
| Realtime (`/v1/realtime`) | Низкоуровневые постоянные маркеры и эффекты элементов | Явное обновление/удаление; realtime `clear` очищает только этот слой |
| Задания (`/v1/jobs`) | До 64 независимо идентифицируемых заданий | Явное обновление/удаление; jobs `clear` очищает только этот слой |

Задания отображают работу внешнего приложения, а не запускают её: сервер
не является очередью исполнителей и не предоставляет паузу/возобновление
отдельного задания. Сценарный проигрыватель остаётся одиночным; параллельные
процессы представляются отдельными заданиями или realtime-ID.
Глобальная остановка очищает все три слоя.

Анимация работает поверх автоматически построенного графа и не меняет
сущности, атрибуты, маршруты, историю отмены или файлы. Подсветка и движущиеся
маркеры не попадают в экспорт SVG/PNG. Смена представления, переход к сравнению
или сброс расчёта графа останавливают анимацию. API работает в режиме просмотра
и редактирования, включая импортированные графы: редактируемая копия не нужна.
Команд изменения документа или размещения отдельных узлов нет.

| Метод | Путь | Ответ JSON / действие |
| --- | --- | --- |
| GET | `/v1/capabilities` | Версия API, возможности (включая `flowchart_shapes`), команды заданий, статусы и лимиты; доступно и без активного графа |
| GET | `/v1/graph` | `{graph_id,type,nodes:[{id,label,shape?}],edges:[{index,source,target,label,direction}]}` |
| GET | `/v1/animation` | `{graph_id,running}` — состояние воспроизведения |
| POST | `/v1/animation` | Запускает сценарий вместо текущего; `{accepted:true,duration_ms}` |
| POST | `/v1/animation/stop` | Пустое тело; останавливает сценарий, удаляет realtime-эффекты и задания; `{stopped:true}`, даже вне представления графа |
| GET | `/v1/realtime` | `{graph_id,markers,elements}` — постоянное визуальное состояние |
| POST | `/v1/realtime` | Атомарно применяет команды реального времени; `{accepted:true}` |
| GET | `/v1/jobs` | `{graph_id,jobs:[...]}` — задания, этапы, цели и прогресс |
| POST | `/v1/jobs` | Атомарно создаёт/обновляет/удаляет задания; `{accepted:true,job_count}` |

Для POST с JSON передавайте `Content-Type: application/json` и `Content-Length`
(обычные клиенты Python/PowerShell выставляют длину автоматически).
Сначала получите `/v1/graph`. Для узлов используются строковые `id`
из ответа, для связей — **индексы** `index` с нуля, а не ID связей из документа.
Это позволяет различать параллельные связи. Полученный `graph_id` передавайте
без изменений; после изменения графа получите описание повторно.
Поле `type` имеет значение `graph` или `flowchart`. Для блок-схем в узлах
передаётся необязательная каноническая фигура `shape`: `process`, `terminator`,
`decision`, `input_output`, `preparation`, `subprocess`, `database` или
`connector`. Сценарии анимации адресуют узлы по ID, а рёбра — по индексам из
дескриптора.
Неизвестные или неоднозначные ID сущностей и неизвестные индексы отклоняются.

При наведении на сущность или связь видны название выполнения, этап, статус,
текущий и целевой прогресс маркера. Несколько ID могут одновременно
использовать одну цель: маркеры разнесены по дорожкам. На узлах отображаются
краткие название, ID, статус и этап; у маркеров — название и текущий прогресс.
Длинные подписи сокращаются, узел показывает до трёх индикаторов со счётчиком
остальных. Полные сведения доступны в подсказках. Раскрываемый список заданий
показывает все jobs; кнопка узла фокусирует его, кнопка маршрута — исходный узел.

Формат сценария:

```json
{
  "graph_id": "ЗНАЧЕНИЕ_ИЗ_GET_GRAPH",
  "steps": [
    {"at_ms": 0, "command": {"type": "highlight", "nodes": ["a"], "edges": [0], "pulse": true, "duration_ms": 2000}},
    {"at_ms": 0, "command": {"type": "camera", "node": "a", "zoom": 1.5, "duration_ms": 800}},
    {"at_ms": 800, "command": {"type": "flow", "edge": 0, "color": [40, 200, 255], "duration_ms": 1800}},
    {"at_ms": 2600, "command": {"type": "clear"}}
  ]
}
```

Замените `a`, `0` и `graph_id` значениями из описания своего графа.
`at_ms` по умолчанию равен `0`, отсчитывается от принятия сценария интерфейсом,
а не от времени отправки. Шаги сортируются по времени; при одинаковом времени
порядок соответствует входному массиву.

| Команда | Поля и поведение |
| --- | --- |
| `highlight` | Массивы `nodes` и/или `edges`, необязательные RGB `color` и `pulse`; подсветка на `duration_ms` |
| `flow` | Обязательный `edge`, необязательные RGB `color` и `reverse`; маркер движется по готовому маршруту с учётом его длины |
| `flow_percent` | Обязательные `edge` и `to_percent`, необязательный `from_percent` (по умолчанию 0); движение по процентному участку за `duration_ms`, с теми же `color`/`reverse`, что у `flow` |
| `camera` | `node` и/или `zoom`, либо `fit:true`; плавное перемещение/масштабирование за `duration_ms` |
| `clear` | Убирает предшествующие эффекты и команды камеры; последующие шаги продолжаются, положение камеры не сбрасывается |

Например, `{"type":"flow_percent","edge":0,"from_percent":25,"to_percent":75,"duration_ms":2000}`
проигрывает среднюю половину связи за две секунды. Процент измеряется по длине
маршрута, включая повороты и петли: `0 <= from_percent <= to_percent <= 100`.
Маркер сценария исчезает после окончания команды; для сохранения конечного
положения используйте маркеры реального времени ниже.

Значения по умолчанию: `duration_ms:1000`, `color:[255,180,40]`,
`pulse:false`, `reverse:false`, `fit:false`, пустые массивы целей.
Подсветка требует хотя бы одну цель. Маркер идёт от сохранённого `source`
к `target` независимо от направления стрелки; `reverse:true` меняет направление
движения, в том числе по петле. Масштаб камеры: `0.15..3`; `fit` несовместим
с `node` и `zoom`. Последняя наступившая команда камеры заменяет предыдущую.
После завершения движения камера остаётся в конечной позиции и снова
принимает ручную прокрутку/масштабирование, даже если другие эффекты ещё идут.

Ограничения: 1–256 шагов, 1–60000 мс на команду кроме `clear`,
конец сценария не позднее 600000 мс, до 1024 целей в одной подсветке,
тело запроса до 65536 байт, заголовки до 8192 байт.
Неизвестные поля JSON отклоняются. Ошибки имеют вид `{"error":"..."}`:
`400` — неверный сценарий/запрос, `401` — нет токена или он неверен,
`403` — неверный Host или браузерный Origin, `404` — неизвестный путь,
`408` — тайм-аут передачи, `409` — неактивный/неготовый граф либо устаревший
graph_id, `413` — превышен размер, `415` — неверный Content-Type,
`503` — очередь недоступна, `504` — интерфейс не ответил вовремя.
Просроченные команды из очереди не выполняются позже.
Поддерживается HTTP/1.1 с длиной тела, без chunked и `Expect: 100-continue`.

**Пример на Python без сторонних пакетов:**

```python
import getpass
import json
import urllib.request

base = input("Адрес API из StructView: ").rstrip("/")
token = getpass.getpass("Bearer-токен: ")

def request(path, body=None):
    headers = {"Authorization": f"Bearer {token}"}
    data = None
    if body is not None:
        headers["Content-Type"] = "application/json"
        data = json.dumps(body).encode("utf-8")
    req = urllib.request.Request(base + path, data=data, headers=headers)
    with urllib.request.urlopen(req, timeout=5) as response:
        return json.load(response)

graph = request("/v1/graph")
if not graph["edges"]:
    raise RuntimeError("Откройте граф хотя бы с одной связью")
edge = graph["edges"][0]
print(request("/v1/animation", {
    "graph_id": graph["graph_id"],
    "steps": [
        {"command": {"type": "highlight", "nodes": [edge["source"]], "pulse": True}},
        {"command": {"type": "camera", "node": edge["source"], "zoom": 1.5}},
        {"at_ms": 1000, "command": {"type": "flow", "edge": edge["index"], "duration_ms": 3000}},
    ],
}))
print(request("/v1/animation"))
# Для досрочной остановки отправьте POST без тела:
stop = urllib.request.Request(base + "/v1/animation/stop",
    method="POST", headers={"Authorization": f"Bearer {token}"})
# urllib.request.urlopen(stop, timeout=5).close()
```

#### Задания: независимые выполнения

Используйте `/v1/jobs` для прикладных задач, чтобы не согласовывать вручную
ID маркера и эффекта элемента. Старые сценарный и realtime API остаются
совместимыми и независимыми. Задание содержит постоянный ID, название, этап,
статус, целевые узлы, необязательный маршрут и прогресс внутри этапа.

Получите `/v1/capabilities`, затем `/v1/graph`, чтобы узнать возможности,
лимиты, ID узлов и индексы связей. Пример атомарного пакета:

```json
{
  "graph_id": "ЗНАЧЕНИЕ_ИЗ_GET_GRAPH",
  "commands": [
    {"type": "upsert", "id": "order-42", "label": "Order #42", "stage": "Capturing payment",
     "status": "running", "nodes": ["payment"], "edge": 0, "percent": 45,
     "color": [40, 160, 255], "smoothing_ms": 300},
    {"type": "upsert", "id": "risk-42", "label": "Risk review #42", "stage": "Checking payment",
     "status": "running", "nodes": ["payment"], "edge": 0, "percent": 30,
     "color": [255, 160, 40]}
  ]
}
```

Замените `payment`, `0` и `graph_id` значениями из дескриптора своего графа.

- `upsert` передаёт **полный снимок**, а не частичное изменение.
  Обязательны `id`, `label`, `stage`, `status`; допустимые статусы:
  `waiting`, `running`, `success`, `error`. Нужны `nodes` и/или `edge`.
  Обновление одного задания не затрагивает остальные, даже на общих целях.
- Необязательные поля: `nodes:[]`, `edge:null`, `percent:0`, `reverse:false`,
  `smoothing_ms:300` и RGB `color`. Без цвета сохраняется прежний цвет задания;
  новый ID получает стабильный цвет из палитры.
- В пределах одного этапа, связи и направления целевой прогресс не уменьшается,
  видимая позиция сохраняется. Смена любого из этих полей создаёт новый маркер
  с нуля. Для повторной попытки используйте **новое название этапа**.
  Задание без маршрута показывает принятый процент.
- `GET /v1/jobs` возвращает полные снимки с выбранным `color`, принятым
  целевым `percent` и сглаженным `current_percent`. Успешные и ошибочные задания
  остаются до удаления. Список показывает целевой прогресс, подписи маршрута
  и подсказки — текущий видимый.
- `{"type":"remove","id":"risk-42"}` удаляет только это задание;
  `{"type":"clear"}` очищает только jobs. Обе команды передаются в массиве
  `commands` вместе с `graph_id`. Неизвестный ID возвращает `400`.
- Пакет содержит 1–64 команды; всего допустимо до 64 заданий. ID — непустой,
  до 128 байт UTF-8; название и этап — непустые, до 256 байт каждый.
  `percent` — `0..100`, сглаживание — `16..10000` мс; до 1024 целей на задание.
  Неверный пакет не меняет прежнее состояние. Устаревший `graph_id`
  возвращает `409`. Общие ограничения транспорта, авторизация и TLS сохраняются.
- Смена представления, перерасчёт графа, выключение API и глобальная остановка
  удаляют все три слоя. Задания не меняют документ, не экспортируются
  и не сохраняются на диск.

#### Маркеры и состояния элементов в реальном времени

Realtime-обновления работают одновременно со сценарием: запуск нового
сценария и его команда `clear` не удаляют этот слой.
`GET /v1/animation` сообщает только о сценарии. `GET /v1/realtime` возвращает
ID маркеров, индексы связей, текущий `percent`, целевой `target_percent`,
цвет, направление и сглаживание; для эффектов элементов — ID эффекта,
ID сущностей, индексы связей, статус, цвет и пульсацию. Маркеры и эффекты
также возвращают необязательные `label` и `stage`.
Передавайте обновления через `POST /v1/realtime`:

```json
{
  "graph_id": "ЗНАЧЕНИЕ_ИЗ_GET_GRAPH",
  "commands": [
    {"type": "marker", "id": "transfer-42", "edge": 0, "percent": 37.5, "smoothing_ms": 300, "color": [40, 200, 255]},
    {"type": "element", "id": "worker-state", "nodes": ["a"], "edges": [0], "status": "running"}
  ]
}
```

- Маркер появляется на `0%` и плавно движется к максимальному проценту,
  полученному для своего ID. Обновления `37.5 -> 60 -> 100` меняют цель,
  не сбрасывая позицию и не перезапуская движение. Запоздалое меньшее значение
  не двигает его назад. ID независимы: по одной связи могут идти разные задачи.
- `smoothing_ms` по умолчанию равен `300` и задаёт постоянную времени
  экспоненциального сглаживания, **а не фиксированную длительность движения**:
  за один интервал проходит около 63% оставшегося расстояния, за три — около
  95%. Остаток менее `0.01` процентного пункта доводится точно до цели.
  Частота запросов может превышать частоту кадров; движение зависит от
  прошедшего времени, а не числа обновлений.
- `percent` — число `0..100`, `smoothing_ms` — `16..10000`.
  `reverse:true` помещает начало прогресса на целевой конец связи.
  Достигнув цели, маркер остаётся на месте до удаления; завершённые неподвижные
  маркеры не требуют постоянной перерисовки.
- Существующему маркеру нельзя менять связь или направление. Сначала передайте
  `{"type":"remove_marker","id":"transfer-42"}`, затем используйте ID снова —
  в том числе для нового отсчёта от нуля. Удаление и создание можно объединить
  в одном атомарном пакете.
- `element` полностью заменяет эффект с тем же ID. Укажите `nodes` и/или
  `edges`. `status`: `waiting` — ожидание/серый; `running` — выполнение/синяя
  пульсация; `success` — успех/зелёный; `error` — ошибка/красная пульсация.
  На сущностях также отображается локализованная подпись статуса.
  Явные `color:[r,g,b]` и `pulse:true/false` переопределяют настройки статуса.
  Без статуса используется постоянная янтарная подсветка.
- `{"type":"remove_element","id":"worker-state"}` удаляет эффект.
  `{"type":"clear"}` в `/v1/realtime` очищает **только** realtime-слой.
  Удаление неизвестного ID возвращает `400`, а не скрывает ошибку.
- `marker` и `element` принимают необязательные `label` и `stage`:
  непустые строки до 256 байт UTF-8 каждая. Они отображаются в подписях
  и подсказках. Для параллельных выполнений используйте разные ID.
- Пакет содержит 1–256 команд и применяется атомарно: неверная цель,
  устаревший graph_id, некорректные параметры или превышение лимита не меняют
  визуальное состояние. Одновременно допускается до 256 маркеров и эффектов
  элементов суммарно. ID должен быть непустым и не длиннее 128 байт UTF-8;
  один эффект может охватить до 1024 сущностей/связей. Общие ограничения
  размеров тела и заголовков сохраняются.
- Смена представления, перерасчёт графа, выключение сервера и кнопка
  **Остановить анимацию** очищают все три слоя, включая jobs.
  Данные графа и экспорт не меняются.
  Параллельные клиенты обрабатываются в порядке очереди интерфейса;
  максимальный процент защищает маркеры от перестановки обновлений,
  а для статуса действует последнее применённое обновление.
  Несовпадение graph_id возвращает `409`.

**Пример отправителя на Python** с функцией `request()` и переменной `base`
из предыдущего примера (одинаковые вызовы для HTTP и HTTPS):

```python
import time

graph = request("/v1/graph")
if not graph["edges"]:
    raise RuntimeError("Откройте граф хотя бы с одной связью")
edge = graph["edges"][0]

def send_progress(percent, status="running"):
    return request("/v1/realtime", {
        "graph_id": graph["graph_id"],
        "commands": [
            {"type": "marker", "id": "job-42", "edge": edge["index"],
             "percent": percent, "smoothing_ms": 300},
            {"type": "element", "id": "job-42-state",
             "nodes": [edge["target"]], "status": status},
        ],
    })

# В рабочем приложении вызывайте send_progress() из уведомлений о прогрессе.
for percent in (10, 30, 80, 45, 100):  # запоздалое 45 не откатывает маркер
    send_progress(percent)
    time.sleep(0.03)
send_progress(100, "success")
print(request("/v1/realtime"))
# Очистить realtime-эффекты, не останавливая сценарий:
# request("/v1/realtime", {"graph_id": graph["graph_id"],
#                         "commands": [{"type": "clear"}]})
```

#### Сетевой HTTP, встроенный HTTPS и обратный прокси

Это сервер **в запущенном GUI-приложении**, а не отдельный фоновый демон.
Оставьте приложение и представление графа открытыми.
Настройте параметры до включения сервера:

1. **IP прослушивания** — LAN-адрес компьютера; `0.0.0.0`/`::` означает все
   IPv4/IPv6-интерфейсы. Безопасное значение по умолчанию — `127.0.0.1`.
2. Для любого адреса вне loopback включите **Разрешить сетевой доступ**.
3. Для доступа с других компьютеров задайте фиксированный порт. При
   прослушивании всех интерфейсов обязательно заполните **Публичный IP или
   DNS-имя** тем адресом, по которому будут обращаться клиенты — **без**
   схемы, порта и пути. Для конкретного IP это поле необязательно, но нужно,
   если клиенты используют DNS-имя. IPv6-адрес в URL записывается в скобках.
   Меню отдельно показывает клиентский URL и фактический сокет прослушивания.
4. Разрешите входящие подключения в системном брандмауэре только доверенным
   клиентам. Приложение не меняет правила и не открывает порты маршрутизатора.

**HTTP:** оставьте HTTPS выключенным. Используйте только в доверенной LAN,
либо слушайте loopback за HTTPS-прокси. Токен обязателен даже на loopback,
но обычный HTTP не шифрует его.

**Встроенный HTTPS:** включите **HTTPS (TLS)**, выберите PEM-файл цепочки
сертификатов (сначала серверный, затем промежуточные) и соответствующий
PEM-файл приватного ключа. SAN сертификата должен содержать DNS-имя/IP,
используемый клиентами. Поддерживаются ключи PKCS#8, RSA PKCS#1 и SEC1
в пределах поддержки rustls; ключ должен быть незашифрованным.
Отсутствующие, некорректные или несовпадающие файлы блокируют запуск
и показывают ошибку; автоматического отката к HTTP нет.
Защитите приватный ключ правами файловой системы, храните вне репозитория
и не добавляйте в git. Сертификаты читаются при запуске; после продления
выключите и повторно включите сервер. Поддерживаются TLS 1.2/1.3.
Авторизация остаётся по API-токену, а не по клиентским сертификатам.
Используйте доверенный сертификат или явно доверенный внутренний CA,
не отключайте проверку сертификата.

Для Python с внутренним CA добавьте `import ssl`, создайте
`tls_context = ssl.create_default_context(cafile=r"C:\certs\ca.pem")`
и передайте `context=tls_context` в `urllib.request.urlopen`.
Для публично доверенного сертификата достаточно базы с `https://`.
PowerShell использует системное хранилище доверия: установите внутренний CA
туда и используйте HTTPS-адрес из меню. Не обходите проверку сертификатов.

**HTTPS через обратный прокси:** оставьте StructView на
`127.0.0.1:8088` (или другом фиксированном порте) без встроенного HTTPS.
Завершайте TLS в прокси, сохраняйте `Authorization`, ограничьте круг клиентов
и замените `Host` на внутренний адрес/порт, ожидаемый StructView.
Например, блок nginx:

```nginx
location /v1/ {
    proxy_pass http://127.0.0.1:8088;
    proxy_set_header Host 127.0.0.1:8088;
    proxy_set_header Authorization $http_authorization;
    proxy_http_version 1.1;
    proxy_request_buffering on;
    proxy_set_header Expect "";
}
```

Настройте HTTPS/сертификаты и список разрешённых клиентов в серверном блоке
прокси. Запросы всё ещё должны содержать `Content-Length`; chunked не
поддерживается. Не удаляйте браузерный `Origin`, чтобы обойти ограничение API,
и не помещайте токен в клиентский JavaScript.
Сервер принимает до 8 одновременных клиентов. Чтение запроса и TLS-handshake
ограничены 2 секундами, отдельно от 2-секундного ожидания ответа интерфейса.
Медленный клиент не блокирует остальных. При превышении лимита HTTP
возвращает `503`, а лишнее TLS-подключение закрывается до handshake.
Выключение дожидается завершения потоков клиентов и освобождает порт;
может потребоваться короткое ожидание до их предельного времени ввода-вывода.

1. Откройте файл в StructView, выберите «Граф и блок-схема» и дождитесь завершения
   расчёта раскладки и маршрутов.
2. Включите API анимации, скопируйте отображаемый URL и Bearer-токен.
3. Из корня репозитория запустите (замените адрес API на адрес из приложения):

```powershell
python tests\demo_graph_animation.py --api http://127.0.0.1:8088 --step-by-step
```

Введите токен в скрытом приглашении. Также поддерживается переменная окружения
`STRUCTVIEW_API_TOKEN`; не помещайте настоящий токен в исходники или аргументы
командной строки. Для HTTPS укажите HTTPS-адрес и при необходимости
`--ca C:\certs\ca.pem`; проверка сертификатов остаётся включённой.

По умолчанию **ничего не запускается автоматически**. Откройте адрес
локальной панели, напечатанный контроллером (обычно `http://127.0.0.1:8765`),
и выберите **Both**, **Scheduled** или **Realtime**. С `--step-by-step`
переходы между главами ожидают кнопку **Next chapter**; без этого флага
используются паузы по времени. Для немедленного старта добавьте `--autoplay`.

- **Scheduled, главы 1–9:** вписывание графа, фокус и масштаб камеры,
  статическая и пульсирующая подсветка, полный проход, участок 25–75%,
  обратное движение и сценарная очистка. Возможности показаны по одной,
  без одновременной анимации всех связей.
- **Полный сценарный проход, глава 9a:** все узлы и связи по непрерывным
  маршрутам от входа до выхода, включая ветки и ограниченный обход циклов.
- **Realtime/jobs, главы 10–21:** ожидающее задание, живой прогресс и
  запоздалое меньшее значение, второе задание на том же маршруте и узле,
  смена этапа/места, ошибка, повторная попытка, удаление одного задания,
  совместимость с legacy realtime, независимая очистка и просмотр состояния.
  В главах 19–20 все маршруты сначала проходит одна задача, затем каждая из
  двух независимых параллельных задач, включая разные ветки. Одновременно
  в демо не более двух заданий.
- Пояснение главы видно в панели и консоли. Держите StructView рядом:
  проверяйте подписи, подсказки при наведении и список заданий с переходом
  к узлу. Контрольные точки не замораживают сценарный проигрыватель:
  временные эффекты завершаются до ожидания, задания остаются для осмотра.
- Кнопки **Both**, **Scheduled**, **Realtime**, **Stop / clear** позволяют
  повторить демонстрацию или очистить эффекты. Состояние и ошибки видны
  в панели и консоли. Одновременно выполняется только одна демонстрация.
- **Камера:** вписать граф, перейти к выбранной сущности, задать масштаб
  (0,15–3). В панели выбираются сущность, связь, цвет, длительность,
  пульсация и обратное направление.
- **Ручные эффекты:** подсветка/пульсация, полный проход, процентный участок,
  realtime-процент с настраиваемым сглаживанием, все четыре статуса
  с необязательным собственным цветом/пульсацией, название и этап выполнения,
  удаление маркера/эффекта. Кнопки **Create / update job**, **Stop this job**
  и **Clear jobs only** управляют заданиями по ID. Все три слоя очищаются
  раздельно; **Stop / clear** очищает всё.
- **Просмотр API / JSON-консоль:** возможности и лимиты сервера, задания,
  дескриптор графа, состояние сценария и realtime-слоя. Можно отправить
  произвольный JSON в поддерживаемые endpoints; `graph_id` берётся из проверенного графа.
  Ошибки API отображаются в панели. Перед ручными изменениями остановите
  автоматическое демо, чтобы не заменять его сценарии; просмотр доступен всегда.

Индексы связей берутся из `/v1/graph`, а ID сущностей и связи сверяются
с TOML-файлом: другой граф отклоняется. Запуск демо останавливает прежнюю
анимацию и удаляет задания. Итоговые завершённые задачи остаются после
realtime-тура для осмотра; удалите их кнопкой **Stop / clear**.
Длительность тура зависит от количества и длины маршрутов, скорости и времени запросов;
контрольные точки могут ждать сколько нужно.
Оставляйте представление графа активным. Ctrl+C останавливает воспроизведение,
очищает эффекты и закрывает демо-сервер.
Браузер обращается только к локальному контроллеру; тот отправляет
авторизованные запросы в StructView. Токен StructView не попадает в страницу.
Контроллер проверяет поддержку jobs через `/v1/capabilities`. Если API
устарел, пересоберите и перезапустите StructView.

Параметры: `--mode scenario|realtime|both`, `--speed 0.1..10`,
`--port 0` для свободного порта панели, `--graph ПУТЬ` для файла графа или
блок-схемы, `--autoplay` для немедленного старта с паузами по времени,
`--step-by-step` для ручного перехода между главами, `--once` для немедленного
однократного запуска без панели. `--once` нельзя сочетать с `--step-by-step`;
обычное завершение `--once` не очищает итоговое задание, в отличие от Ctrl+C:

```powershell
python tests\demo_graph_animation.py --api http://127.0.0.1:8088 --mode both --once --speed 2
python -B -m unittest discover -s tests -p test_demo_graph_animation.py -v
```

### Большие файлы и производительность

GUI хранит разобранный документ в памяти, но дерево использует виртуализацию
строк: при раскрытии большого поддерева egui создаёт виджеты только для строк,
попавших в текущую область просмотра. Прокрутка, выбор, редактирование,
поиск и контекстные меню при этом работают со всем деревом.

Виртуализация уменьшает стоимость отрисовки полностью раскрытого дерева, но
не делает расход памяти постоянным. При открытии файла приложение по-прежнему
читает его целиком и строит полное дерево в памяти, поэтому расход памяти
пропорционален числу узлов. Для особенно больших файлов лучше оставлять
несвязанные ветки свёрнутыми, а для операций без интерактивного просмотра
использовать команды CLI `find`, `validate`, `format` и `diff`.

При сохранении формат выбирается по расширению файла. Если расширение не
поддерживается, используется формат открытого документа.

Чтобы преобразовать открытый документ, выберите `Файл -> Преобразовать в` и
укажите `JSON`, `YAML`, `TOML` или `JSON5` (текущий формат скрыт). В диалоге
предлагается имя с расширением целевого формата, а результат записывается в
отдельный файл; открытый документ не изменяется. Данные `JSON5` записываются
через совместимое с JSON представление: комментарии сохраняются только при
записи в поддерживающий их формат, а завершающие запятые нормализуются.

### Сравнение файлов

Режим сравнения разбирает каждый выбранный файл тем же способом, что и
обычный просмотрщик. Объекты и массивы сравниваются рекурсивно, поэтому в
таблице показываются наиболее глубокие изменённые пути. Отсутствующий путь
отличается от JSON-значения `null`. В общей таблице отличия подсвечиваются
относительно первого файла: добавления — зелёным, удаления — красным,
изменения — жёлтым. Можно переключаться между общей таблицей отличий и парным
diff; если загружено больше двух файлов, версии выбираются в списках над diff.
Если открыт документ и для сравнения выбран один другой файл, открытый документ
становится первой версией, а приложение сразу показывает парный diff. Режим
сравнения предназначен только для просмотра;
используйте `Файл -> Открыть…` или `Файл -> Закрыть файл`, чтобы вернуться к
обычному документу.
Выбранная пара сравнивается рекурсивно независимо от остальных файлов, даже
если в другом файле соответствующий контейнер имеет другой тип.

### Обработка форматов и ограничения

Даты и время TOML сохраняют собственный тип при обратной записи в TOML, как и
различие между целыми и вещественными числами `1` и `1.0`. При преобразовании
дат/времени в JSON и другие JSON-совместимые представления они становятся
строками. Значения TOML `nan` и infinity сохраняются в TOML, но не могут быть
преобразованы в JSON, YAML или JSON5 через общую JSON-совместимую модель.
TOML не поддерживает `null`.

Значения JSON5 `NaN`, `Infinity` и числовые литералы с переполнением до
бесконечности явно отклоняются, а не заменяются молча на `null`.

Поток из нескольких YAML-документов отображается как массив. Нестроковые
ключи YAML показываются в компактной JSON-записи; если после такого
преобразования ключи совпадают, разбор завершается ошибкой вместо молчаливой
потери данных. YAML-теги значений отображаются отдельными узлами `Metadata` и
сохраняются при записи в YAML; преобразование в формат без поддержки тегов
завершается ошибкой, а не теряет их. Теги ключей YAML и нечисловые значения
NaN/Infinity по-прежнему не поддерживаются. Комментарии JSON5, YAML и TOML
отображаются отдельными узлами и сохраняются при записи в поддерживающий их
формат. При сохранении комментарии нормализуются в отдельные строки в начале
файла; исходные позиции и стиль комментариев, YAML-якоря и форматирование не
сохраняются. При преобразовании в строгий JSON комментарии отбрасываются,
завершающие запятые нормализуются.

При редактировании существующего поля сохраняется его точное имя, включая
пустые имена и пробелы по краям. Новые имена полей обрезаются по краям и не
могут быть пустыми. Конструктор вещественного числа отклоняет текст, который
выбранный формат разобрал бы как строку. Экспорт CSV использует ту же
атомарную замену файла, что и сохранение документа: ошибка записи не обрезает
существующий файл.

При открытии или создании другого файла несохранённые изменения вызывают
подтверждение: сохранить, не сохранять или отменить действие. Учитывается и
документ, скрытый режимом сравнения. Такое же подтверждение защищает изменённый
исходник схемы структуры и закрытие окна приложения системной кнопкой.
Если изменены и обычный документ, и его независимый снимок в схеме структуры,
сохраните каждое представление отдельно перед заменой документа.
Ошибка сохранения или чтения файла не удаляет текущие данные.
Импортированный граф нельзя перезаписать преобразованием или командой
«Сохранить как», в том числе через символическую ссылку на исходный файл.

### Копирование структур между файлами

1. Откройте исходный файл и выберите один или несколько узлов дерева. Для
   нескольких узлов удерживайте `Ctrl` (Windows/Linux) или `Cmd` (macOS).
2. Выполните `Ctrl+C`/`Cmd+C` или выберите команду копирования в меню
   `Правка`.
3. Откройте файл назначения, включите режим `Редактирование` и выберите
   объект или массив, в который нужно вставить данные.
4. Выполните `Ctrl+V`/`Cmd+V` или используйте `Вставить сюда` в контекстном
   меню выбранного контейнера.

Вложенные объекты и массивы копируются целиком. При вставке в объект
сохраняются имена полей, а при вставке в массив элементы добавляются в конец
с новыми индексами. Если скопирован корневой объект или массив без ключа, его
поля или элементы добавляются в целевой контейнер. Вставка не изменяет файл на
диске до выполнения команды сохранения.

## Командная строка

Выполнить бинарный файл после release-сборки можно напрямую. Во время
разработки те же команды запускаются через `cargo run --`.

В Windows release-сборка сохраняет перенаправленные stdin, stdout и stderr:
подключение к консоли не заменяет каналы и файловое перенаправление.

Основной язык сообщений CLI — английский. Имена команд и опций не зависят от
языка. Подробности ошибок общих парсеров и проверок редактирования могут
содержать локализованный текст.

### Форматирование

Вывести отформатированные данные в stdout:

```sh
struct_view format data.json
```

Записать результат в файл:

```sh
struct_view format data.json --output normalized.json
```

Компактное представление без отступов:

```sh
struct_view format data.json --minify
```

Источник можно передать через stdin, используя `-` или не указывая файл:

```sh
struct_view format - < data.json
```

Формат результата определяется по расширению файла, указанного в `--output`.
Если `--output` не задан, сохраняется формат входных данных.
Вывод в stdout завершается одним переводом строки, даже если сериализатор
уже добавил его (например, для YAML и TOML).

### Проверка синтаксиса

```sh
struct_view validate data.yaml
```

Проверка данных из stdin:

```sh
struct_view validate - < data.toml
```

Команда сообщает распознанный формат при успешной проверке и возвращает
ненулевой код при ошибке разбора.

### Поиск путей

Поиск выполняется по ключам, значениям и JSON-путям и выводит пути найденных
узлов:

```sh
struct_view find user data.json
```

Чтобы найти узел по паре «ключ и значение» на одном узле, используйте
`ключ: значение`:

```sh
struct_view find 'name: Alice' data.json
```

Дополнительные параметры:

```text
--keys            искать в ключах;
--values          искать в значениях;
--paths           искать в JSON-путях;
--case-sensitive  учитывать регистр;
--exact           требовать точное совпадение;
--whole-word      искать целое слово;
--regex           интерпретировать запрос как регулярное выражение Rust.
```

`--regex` нельзя сочетать с `--exact` или `--whole-word`; параметр
`--case-sensitive` действует и для регулярных выражений.

Примеры:

```sh
struct_view find --keys name data.json
struct_view find --values --case-sensitive ADMIN config.json
struct_view find --keys --exact id data.json
struct_view find --paths --regex '^users\.[0-9]+\.name$' data.json
```

Если совпадений нет, команда завершается с ненулевым кодом.

### Сравнение файлов

Сравнить два или более файла и вывести каждый изменённый путь со значениями
из всех входных файлов:

```sh
struct_view diff first.json second.json
struct_view diff base.yaml candidate.yaml generated.json
```

Один источник можно прочитать из stdin через `-`:

```sh
struct_view diff reference.json - < candidate.json
```

Объекты и массивы сравниваются рекурсивно. Каждое отличие выводится отдельным
блоком: путь, имя источника и значение; вложенные объекты и массивы
форматируются на нескольких строках с отступами. Для отсутствующего пути
выводится `<missing>`, а JSON-значение `null` выводится как `null`. Команда
возвращает код `0`, если все источники одинаковы, и код `1`, если найдены
отличия или обнаружена ошибка данных. В качестве синонима `diff` принимается
команда `compare`.

### Чтение, создание и редактирование

Все команды работают без открытия окна. Входной файл можно заменить на `-`
или не указывать: тогда данные читаются из stdin. По умолчанию результат
выводится в stdout; `--output FILE` записывает его в файл, а `--in-place`
у команд редактирования сохраняет исходный файл. Запись атомарная и начинается
только после успешного разбора, изменения и сериализации.

```sh
struct_view new empty.json
struct_view new --to yaml
struct_view convert data.json --to yaml
struct_view get user.name data.json
struct_view get user.name data.json --raw
struct_view get user.name data.json --part key
struct_view get user.name data.json --part path
struct_view add '$' data.json --key enabled --type boolean --value true
struct_view add users data.json --type object
struct_view set user.name data.json --type string --value 'Grace Hopper' --in-place
struct_view rename user.name display_name data.json --output renamed.json
struct_view delete data.json --path users[0] --path obsolete --in-place
```

Пути принимаются в форме, которую выводит `find`, включая `user["a.b"]`,
или с префиксом `$`, как в таблице. `$` обозначает корень.
`copy` и `delete` принимают несколько `--path`; каждый путь проверяется до
изменения документа, а вложенные выделения не обрабатываются повторно.
Удалять корень нельзя.

`get` выводит сериализованное значение. `--part key` выводит имя поля или индекс,
`--part path` — путь; у корня нет ключа. `--raw` выводит строку, TOML-дату
или комментарий как текст без JSON-кавычек.
Извлечённые TOML-значения, кроме объектов, по умолчанию выводятся как JSON:
TOML не поддерживает отдельный скаляр или массив в корне документа.
`--to` позволяет явно выбрать другой формат.

`new` создаёт пустой объект и отказывается перезаписывать существующий файл,
даже если другой процесс создаёт его во время выполнения команды.
`new`, `convert`, `get` и команды редактирования поддерживают
`--to json|yaml|toml|json5` и `--minify`. Без `--to` формат задаёт расширение
выходного файла, иначе сохраняется входной формат. Противоречие между `--to`
и расширением результата отклоняется. Импортированные графы преобразуются
по умолчанию в JSON; редактировать и перезаписывать исходные графовые файлы
нельзя, включая файлы с расширением `.xml`.

Типы конструктора `add` и `set` совпадают с GUI:

| `--type` | `--value` |
| --- | --- |
| `string` | обычный текст, не строковый литерал в кавычках |
| `number`, `float` | числовой литерал; `float` сохраняет вещественный тип |
| `boolean` или `bool` | `true` или `false` |
| `null`, `object`, `array` | без `--value`; новые контейнеры пустые |
| `datetime` | нативная дата/время, только для TOML |
| `comment` | текст комментария, только для JSON5/YAML/TOML |
| `metadata` | YAML-значение с тегом, например `!custom value` |

Для нового поля объекта `add` требует `--key`; элементы массива добавляются
в конец. `set --key` также переименовывает поле. Новые имена обрезаются
по краям, должны быть непустыми и уникальными. Как в GUI, установка того же
типа контейнера сохраняет его содержимое; для вставки заполненных структур
используйте `paste`. Ограничения дат, комментариев и YAML-тегов те же, что
при редактировании и сохранении в GUI.

### Копирование и вставка структур

```sh
struct_view copy source.json --path user --path settings --output selection.json
struct_view paste '$' target.json --from selection.json --in-place
struct_view copy source.json --path user | struct_view paste '$' target.json --in-place
struct_view copy source.json --path user --clipboard
struct_view paste '$' target.json --clipboard --output pasted.json
```

`copy` выдаёт совместимый с GUI JSON-конверт выделения, сохраняя ключи
и вложенные структуры. `paste` принимает такой конверт или обычный JSON
из `--from FILE` (или `-`), по умолчанию из stdin. Только один источник
может быть stdin. Корневой объект без ключа вставляется своими полями,
корневой массив — своими элементами. Записи с ключами сохраняют имена
при вставке в объект, в массив добавляются их значения. Повторные ключи
отклоняются, а не перезаписываются.

`--clipboard` явно использует системный буфер обмена вместо потока выделения.
Для этого нужен доступный буфер платформы; остальные команды, включая экспорт
изображений, не требуют графического сервера.

### Экспорт таблицы, схемы и графа

```sh
struct_view table data.json --output table.csv
struct_view table data.json --query name --keys --exact
struct_view schema data.json --output schema.json
struct_view schema api.yaml --query id --keys
struct_view graph network.graphml --output graph.json
struct_view graph network.graphml --output graph.svg
struct_view graph network.graphml --output graph.png --dark
```

`table` экспортирует таблицу GUI в CSV с колонками `path,value,type`,
включая контейнеры, пустые значения, комментарии и нативные типы.
`table` и `schema` принимают `--query` и все параметры поиска `find`.
Отсутствие совпадений — успешный пустой экспорт: заголовок CSV
или пустой список строк схемы.

`schema` экспортирует модель диаграммы GUI, а не генерирует контракт JSON Schema.
Поле `source` равно `json-schema`, `openapi` или `inferred`; `title`
может быть `null`, а `rows` содержит `key`, `path`, `type`, `required`,
`constraints`, `reference`. Схема, выведенная из примера, явно помечена `inferred`.

`graph` выдаёт JSON-модель GUI: `directed`, `direction`, `partitions`, `nodes`
(`id`, `label`, `path`, `partition`) и `edges` (`source`, `target`, `label`, `direction`).
Сводное `direction` равно `mixed` при разных направлениях; `directed`
означает наличие хотя бы одной стрелки. Направление каждого ребра —
`directed`, `undirected`, `bidirectional` или `reverse`.
Концы рёбер — индексы узлов, начиная с нуля; параллельные рёбра и доли
сохраняются. Если сущности не распознаны, возвращается ошибка.
Петли сохраняются и прокладываются вне карточки узла.
Поля входных форматов, DOT `dir`, GEXF `mutual` и правила GraphML описаны
в [руководстве по графам](./tutorial/ru.md).
GUI и CLI также поддерживают node-link/NetworkX, Cytoscape, словари узлов
и рёбер, кортежи рёбер и списки смежности в JSON, JSON5, YAML и TOML.
Формы данных и правила проверки описаны в разделе
[«Поддерживаемые структуры графов»](./tutorial/ru.md#поддерживаемые-структуры-графов).
Расширение результата `.svg` или `.png` включает экспорт изображения;
можно также указать `--image svg|png --output FILE`.
Используется полная раскладка GUI с полными подписями связей.
По умолчанию изображение светлое с прозрачным фоном; `--dark` задаёт
тёмный непрозрачный фон. PNG при необходимости уменьшается до 16 миллионов
пикселей с сохранением всего графа; SVG сохраняет векторную детализацию.
Масштаб, выделение, тема, язык и undo/redo — действия интерфейса,
а не команды CLI.
Если stderr подключён к интерактивному терминалу, при экспорте изображения
графа показываются этапы, прогресс маршрутов, число потоков, время и итоговые
длительности этапов. При создании таблицы, схемы и модели графа отображаются
индикаторы активности во время чтения, разбора и вычислений. Прогресс выводится
в stderr и не показывается при перенаправлении stderr, поэтому машинный вывод
в stdout не меняется.

CLI использует API без окна в UI-крейте: общие операции редактирования,
конверты выделений, модели визуализаций и существующий рендерер SVG/PNG
в памяти. Нативный GUI не запускается.

## Разработка

Проверить форматирование, запустить тесты и выполнить статический анализ:

```sh
cargo fmt --all -- --check
cargo test --locked --workspace --all-targets --all-features
cargo test --locked --workspace --all-features --doc
cargo clippy --locked --workspace --all-targets --all-features -- -D warnings
```

Проверка Python-контроллера и панели демо:

```powershell
python -B -m unittest discover -s tests -p test_demo_graph_animation.py -v
```

Workflow `Quality checks` в GitHub Actions запускается при push и pull request;
его также можно запустить вручную во вкладке Actions. Проверяются все крейты
workspace, интеграционные тесты CLI и примеры из документации.
Отправка тега версии, совпадающей с версией в `Cargo.toml` (например,
`v0.1.0`), запускает сборку для Linux, Windows и macOS и публикацию архивов в
GitHub Release.

Крейты workspace:

```text
crates/
  struct-view-core/       парсинг, дерево документов, поиск и сравнение
  struct-view-operations/ общие операции редактирования, буфер обмена и модели визуализации
  struct-view-routing/    алгоритмы графов, ортогональная прокладка и список смежности
  struct-view-animation-api/ авторизованный HTTP/HTTPS-транспорт анимации
  struct-view-cli/        разбор аргументов и headless-команды
  struct-view-ui/         GUI, окна редактора, отрисовка и состояние анимации/заданий
  struct-view-build-info/ общие метаданные сборки
src/
  lib.rs                  совместимый фасад над крейтами workspace
  main.rs                 точка входа исполняемого файла
  console.rs              платформенная интеграция с консолью
```

CLI и GUI не зависят друг от друга: оба используют `struct-view-core` и
`struct-view-operations`. Общие операции редактирования, формат буфера обмена,
модель редактируемого графа и модели таблицы/схемы/графа находятся в
[`struct-view-operations`](../crates/struct-view-operations/README.md).
Отрисовка изображений графа остаётся в UI; исполняемый файл передаёт её CLI
через адаптер `GraphImageRenderer`, не добавляя зависимость CLI от UI.
[`struct-view-animation-api`](../crates/struct-view-animation-api/README.md)
не зависит от GUI-фреймворка: приложение передаёт callback пробуждения,
обрабатывает запросы и владеет состоянием графа. Транспорт отвечает за
авторизацию, HTTP/TLS, очереди, лимиты и завершение соединений.
Структура модулей приведена в README каждого крейта; см. также
[обзор workspace](../README.md#development).

Крейт `struct-view-build-info` добавляет сведения о версии Rust, целевой
платформе, времени компиляции и режиме оптимизации. Эти данные доступны через
`--version` и меню `Помощь`.
