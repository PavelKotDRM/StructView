# Туториал: управление графами через API-сервер StructView

[К общему туториалу](ru.md) | [Обзор проекта](../README.ru.md)

Это отдельное практическое руководство по управлению визуализацией графа из
скрипта через встроенный HTTP(S)-сервер. API принимает команды анимации и
отображения состояния процессов, но не редактирует документ, не запускает
фоновые задачи и не сохраняет данные.

## 1. Подготовить граф и включить сервер

Откройте в StructView документ, содержащий граф или блок-схему, переключитесь
в представление **Граф** и дождитесь завершения размещения узлов и связей.
Сервер API работает с текущим активным графом. Узлы графа связей могут
содержать ID, подпись, дополнительные атрибуты и связи с направлением. У узлов
блок-схемы дополнительно можно задавать фигуры.

Поддерживаются два типа графа в ответе API:

- `graph` — обычный граф связей;
- `flowchart` — блок-схема с необязательными фигурами узлов.

Блок-схемы можно описывать в JSON, YAML или TOML. StructView также импортирует
Mermaid, DOT, GraphML и GEXF как графы только для чтения; при работе с API
важен тип и состав уже открытого графа, а не исходное расширение файла.

Откройте **Настройки → API анимации графа** и нажмите **Включить сервер API**.
По умолчанию сервер слушает только локальный интерфейс; порт `0` выбирает
свободный порт автоматически. Скопируйте показанный URL и токен.
При запущенном сервере нажмите **F1**, чтобы увидеть читаемый список методов и
маршрутов API и требования к авторизации. Полная спецификация OpenAPI JSON
открывается из справки в отдельном окне, которое можно увеличить.

Все запросы требуют заголовок `Authorization: Bearer <ТОКЕН>`. Токен создаётся
при включении сервера, не сохраняется в документе и не должен попадать в
публичные логи или клиентский JavaScript. Запросы из браузера с заголовком
`Origin` сервер отклоняет; используйте локальный скрипт или доверенное
нативное приложение. Для удалённого доступа явно включите сетевое
прослушивание и настройте TLS и сетевой экран. Не передавайте токен по
незащищённому HTTP через недоверенную сеть.

## 2. Проверить соединение и получить граф

Ниже пример на Python 3.11+ без сторонних пакетов. Запустите его в терминале,
подставив адрес из окна API. Токен вводится скрыто и не записывается в код.

```python
import getpass
import json
import urllib.request

base = input("API URL: ").rstrip("/")
token = getpass.getpass("API token: ")

def request(path, body=None):
    headers = {"Authorization": f"Bearer {token}"}
    data = None
    if body is not None:
        data = json.dumps(body).encode("utf-8")
        headers["Content-Type"] = "application/json"
    req = urllib.request.Request(base + path, data=data, headers=headers)
    with urllib.request.urlopen(req, timeout=5) as response:
        return json.load(response)

capabilities = request("/v1/capabilities")
graph = request("/v1/graph")
print("Supported API features:", capabilities["features"])
print("Graph type:", graph["type"])
print("Graph ID:", graph["graph_id"])
print("Nodes:", len(graph["nodes"]), "links:", len(graph["edges"]))
print(json.dumps(graph, ensure_ascii=False, indent=2))
```

Сохраните `graph_id`, ID узлов и индексы связей из этого ответа. Не угадывайте
индекс связи по её порядку в файле: используйте поле `index` из `/v1/graph`.
При смене или перестроении графа снова запросите дескриптор и используйте его
новый `graph_id`; запрос со старым ID будет отклонён.

Для узлов блок-схемы ответ может включать `shape`. Допустимые ID фигур:

| ID (`shape`) | Название |
| --- | --- |
| `process` | Процесс |
| `terminator` | Начало / завершение |
| `decision` | Решение |
| `input_output` | Ввод / вывод |
| `preparation` | Подготовка |
| `subprocess` | Подпроцесс |
| `database` | База данных |
| `connector` | Соединитель |

## 3. Запустить сценарий анимации

Сценарий — это последовательность шагов с временем запуска. Команда ниже
подсвечивает узел и связь, переводит камеру к узлу и запускает маркер по
связи. Замените `graph_id`, `node_id` и `edge_index` значениями из ответа
`/v1/graph`.

```python
node_id = graph["nodes"][0]["id"]
edge_index = graph["edges"][0]["index"]

result = request("/v1/animation", {
    "graph_id": graph["graph_id"],
    "steps": [
        {"at_ms": 0, "command": {
            "type": "highlight",
            "nodes": [node_id],
            "edges": [edge_index],
            "pulse": True,
            "duration_ms": 2500
        }},
        {"at_ms": 0, "command": {
            "type": "camera",
            "node": node_id,
            "zoom": 1.4,
            "duration_ms": 700
        }},
        {"at_ms": 800, "command": {
            "type": "flow",
            "edge": edge_index,
            "duration_ms": 1600
        }}
    ]
})
print(result)
print(request("/v1/animation"))
```

`POST /v1/animation` заменяет текущий сценарий. Доступны команды `highlight`,
`flow`, `flow_percent`, `camera` и `clear`. Сценарий удобен для заранее
известной последовательности, но одновременно выполняется только один
сценарий. Маркер команды `flow` исчезает по её завершении.

## 4. Отображать ход внешней задачи

Для реальных параллельных процессов используйте `/v1/jobs`. Задачи — это
только визуальные статусы: отдельные скрипты или службы по-прежнему сами
выполняют работу и отправляют обновления.

```python
job_id = "order-42"

def update_job(stage, percent, status="running"):
    return request("/v1/jobs", {
        "graph_id": graph["graph_id"],
        "commands": [{
            "type": "upsert",
            "id": job_id,
            "label": "Обработка заказа",
            "stage": stage,
            "status": status,
            "nodes": [node_id],
            "edge": edge_index,
            "percent": percent
        }]
    })

update_job("Проверка заказа", 15)
update_job("Резервирование", 60)
update_job("Заказ завершён", 100, "success")

print(request("/v1/jobs"))
```

Статус может быть `waiting`, `running`, `success` или `error`. Поля `nodes`
и `edge` определяют место отображения задачи; `percent` — прогресс этапа от 0
до 100. Повторный `upsert` с тем же `id` обновляет задачу, а новый этап может
начать прогресс заново. Одновременно можно отображать до 64 задач.

Список **Задачи схемы** над графом показывает все задачи. Кнопка перехода
фокусирует узел или связь; кнопки удаления убирают отображение задачи, но не
останавливают внешний процесс. Узлы показывают до трёх бейджей, остальные
доступны при наведении в подробной подсказке.

## 5. Использовать постоянные realtime-эффекты

`/v1/realtime` подходит для низкоуровневых маркеров и статусов, когда модель
задач `/v1/jobs` не нужна. Например, можно передвигать маркер вдоль связи:

```python
request("/v1/realtime", {
    "graph_id": graph["graph_id"],
    "commands": [{
        "type": "marker",
        "id": "worker-7",
        "edge": edge_index,
        "percent": 70,
        "label": "Синхронизация",
        "stage": "Передача данных",
        "smoothing_ms": 300
    }]
})
print(request("/v1/realtime"))
```

Маркеры и элементы realtime остаются видимыми, пока их явно не удалить или не
очистить соответствующий слой. Для независимых задач обычно удобнее `/v1/jobs`:
он атомарно обновляет сведения о задаче и связанные визуальные статусы.

## 6. Остановить и очистить

Удалить только одну задачу:

```python
request("/v1/jobs", {
    "graph_id": graph["graph_id"],
    "commands": [{"type": "remove", "id": job_id}]
})
```

Очистить слой задач можно командой `{"type": "clear"}` на `/v1/jobs`; аналогично
очищается слой `/v1/realtime`. Эти операции не влияют на другие слои.
`POST /v1/animation/stop` останавливает сценарий и очищает realtime-эффекты и
задачи. Он не меняет документ, его историю редактирования или сохранённый файл.

Остановить и отключить сервер можно кнопкой **Выключить API** в StructView.
Повторное включение создаёт новый токен, поэтому внешним клиентам нужно
передать новые учётные данные.

## 7. Диагностика

В окне API при запущенном сервере доступны число активных соединений, очередь,
счётчики успешных и ошибочных запросов и последние 50 endpoint-запросов с
размером команды, HTTP-статусом и длительностью. Содержимое запросов и токены
в истории не сохраняются.

Частые ответы API:

| HTTP | Причина и действие |
| --- | --- |
| `400` | Неверный JSON, команда или параметр; проверьте точные имена полей и типов. |
| `401` | Нет токена или он устарел; скопируйте действующий токен из окна API. |
| `403` | Не совпадает `Host` или передан браузерный `Origin`; отправляйте запрос из скрипта. |
| `404` | Неизвестный endpoint; используйте адреса `/v1/...` из этого руководства. |
| `409` | Граф неактивен, раскладка не готова или `graph_id` устарел; получите `/v1/graph` заново. |
| `413` | Тело запроса превышает лимит 65 536 байт; разбейте пакет. |
| `503` | Очередь заполнена или достигнут лимит клиентов; повторите запрос позже. |
| `504` | GUI не обработал запрос за отведённое время; дождитесь готовности графа и повторите. |

Все обновления пакетов `/v1/jobs` и `/v1/realtime` атомарны: если одна команда
в пакете неверна, пакет целиком отклоняется. Сначала проверьте запросы малым
пакетом и используйте `GET /v1/jobs` или `GET /v1/realtime` для сверки
состояния.

Для полного контракта команд, лимитов, HTTPS и примеров клиентов см. раздел
[Graph animation API в README проекта](../../README.md#graph-animation-api).
